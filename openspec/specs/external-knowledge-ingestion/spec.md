# external-knowledge-ingestion Specification

## Purpose

Define how Growth Knowledge Hub persists host-summarized external materials as long-lived local learning notes without becoming a third-party content mirror.

## Requirements

### Requirement: Ingest host-summarized external material
The system SHALL accept structured material summaries generated by the host CLI from articles, notes, documents, copied material, or third-party knowledge results.

#### Scenario: Host CLI provides material summary input
- **WHEN** the host CLI calls `gkh.py ingest --input <file>` with title, source type, source locator, summary points, key concepts, application ideas, open questions, and tags
- **THEN** the script persists the summary, source locator, provenance, knowledge gaps, and index entries into the local Wiki

### Requirement: Preserve summary-first third-party knowledge
The system MUST persist third-party knowledge as local summaries by default rather than full-content mirrors.

#### Scenario: External source locator is provided
- **WHEN** the source is a third-party item, URL, knowledge-base item, or opaque connector locator
- **THEN** the written page records the locator and `full_content_policy: fetch_on_demand` or equivalent metadata

#### Scenario: Full content is needed later
- **WHEN** a future user question requires details beyond the local summary
- **THEN** the host CLI may retrieve the original source on demand outside the local Wiki persistence path

### Requirement: Limit material summaries to six points
The system MUST keep persisted material summaries compact.

#### Scenario: Summary has more than six points
- **WHEN** material input contains more than six summary points
- **THEN** the script persists no more than six summary points

### Requirement: Retain external summaries long term
The system SHALL treat imported external material summaries as durable local learning knowledge.

#### Scenario: Remote item changes or disappears
- **WHEN** a previously imported third-party item is no longer available or has changed remotely
- **THEN** the system preserves the local summary note and may rely on source locator metadata for future freshness review

### Requirement: Track knowledge gaps from material
The system SHALL preserve unresolved questions from ingested material as local knowledge gaps.

#### Scenario: Material contains open questions
- **WHEN** material input includes open questions
- **THEN** the script writes a knowledge gap page linked to the same raw source and source manifest entry

### Requirement: Separate learning context from capability evidence
The system MUST treat external material as learning context rather than evidence that the user has mastered the topic.

#### Scenario: External material suggests expertise
- **WHEN** imported material describes advanced skills or expert guidance
- **THEN** the system records it as learning context and does not treat it as proof of user capability
